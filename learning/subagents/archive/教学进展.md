**第 4 课 · 怎么给子 agent 一份好指令**（`lessons/0004-how-to-instruct-a-subagent.html`）
- 自包含 prompt 四要素：任务 / 约束 / 输出格式 / 上下文
- 拆解用户写的 raft1 prompt → 三处优化（加广度、输出对齐查询、缩小问题范围），分别落在约束/输出格式/任务三要素
- 反模式清单：含糊、漏约束、无格式、假设它知道、多目标混杂

**第 5 课 · 并行派发多个子 agent**（`lessons/0005-dispatching-parallel-subagents.html`）
- 依据 `superpowers:dispatching-parallel-agents` skill：每个独立问题域派一个 agent、并发跑、统一 review
- 并行三条件：独立 / 无共享状态 / 自包含；不适合：相关任务、改同文件、需全局
- 关键机制：一条消息多个 Agent 工具调用 = 并发；分多条消息 = 串行
- 真实案例（6 失败跨 3 文件 → 3 agent 并行修 → 全绿零冲突）+ review 整合四步

**选学 · SDD 工作流**（`lessons/0006-sdd-workflow.html`）
- 依据 `superpowers:subagent-driven-development` skill
- 核心公式：每任务全新子 agent + 两阶段 review（先 spec 合规、后代码质量）
- 角色分工：控制器（主会话）/ implementer / spec 审查者 / 质量审查者
- 流程循环：派 implementer → 答问 → 实现+测试+提交+自审 → spec 审查 → 质量审查 → 两道都过才进下一任务；全完再 final review
- 关键区分：SDD 串行（任务有依赖）vs 第 5 课并行（独立任务）；两阶段顺序不能错；不让子 agent 读 plan（给全文）
- 呼应 learning-records/0001（用户"设计留主会话、实现派出去"洞察 = SDD 核心）

## 关键洞察 / 案例库

- **用户真实场景**：读两个 PDF → 总结内容并讲解。判定：**适合派**（5/5 命中）。
- **核心拆分技巧**："读 + 总结"派出去（耗上下文的脏活），"讲解讨论"留主会话（交互的部分）。子 agent 返回结构化总结，主会话只收总结再和你聊。
- **四要素是检查清单**：用户 raft1 prompt 的三处优化（加广度 / 输出对齐查询 / 缩小问题范围）正好分别落在约束、输出格式、任务三个要素上——写完 prompt 用四要素过一遍即可。
