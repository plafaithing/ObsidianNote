什么时候该派子 agent

上一课你给了一个真实场景——"读两个 PDF、总结内容并讲解"，我说它适合派。这节课讲清为什么：一套判断框架，让你以后自己能拍板。

适合派的 5 个信号

命中越多，越该派

  • 自包含——能给一份完整简报，不必回看主会话的历史
  • 耗上下文——要读大量文件 / 搜索，结果会塞满主上下文
  • 独立——和主会话正在做的事不紧耦合
  • 要结论——你要的是答案 / 总结，不是过程占用你的注意力
  • 可并行——多个这样的任务能同时跑（第 5 课展开）

不适合派的 4 个信号

命中任意一条，就要犹豫

  • 紧耦合——需要主会话实时状态、频繁来回交互
  • 需看全局——得理解整个系统才能动手
  • 太小——开销大于收益（改个拼写、查一个值）
  • 需你亲自判断——核心决策不该外包

案例：你的"读 PDF"场景

真实场景 · 逐条对照

"给 CC 两个 PDF，让它读完总结内容并讲解。"

✓ 自包含：读文档+总结，简报能写全
✓ 耗上下文：PDF 全文占大量上下文
✓ 独立：和其他事无关
✓ 要结论：要的是总结，不是过程
✓ 可并行：多篇文档可分给多个 agent

5/5 命中 → 非常适合派。

关键洞察：什么派出去、什么留下。
"读 + 总结"是耗上下文的脏活 → 派出去；"讲解、追问、讨论"是要和你来回交互的部分 → 留在主会话。子 agent 返回结构化总结，主会话只收总结，再和你聊。

练一练：该派还是不派？

场景 1：让子 agent 读 5 个源码文件，找出函数 handleRequest 定义在哪。
场景 2：和 CC 一起设计新功能，需要它随时理解整个代码库结构来给建议。
场景 3：三个不相关的 bug，分别在三个文件里。
场景 4：让 CC 把一行代码里的拼写错误改掉。
