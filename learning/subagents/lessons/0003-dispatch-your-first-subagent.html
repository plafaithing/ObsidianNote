亲手派第一个子 agent

前两课讲了"是什么""何时派"。这课真的派一个出去，看全过程。

Agent 工具怎么用

派子 agent 只需两个必备输入：

  • subagent_type——派哪种（如 Explore 搜索、Plan 规划、general-purpose 通用）
  • prompt——给它什么任务（自包含的指令）
Agent(
  subagent_type: "Explore",
  prompt: "扫描 D:\\workplace\\code\\test 的代码结构，
           返回文件清单、依赖关系、入口。
           只读，不贴大段源码。"
)

实战：派 Explore 扫一个项目

我给它的 prompt（注意四要素）：

广度：medium。
扫描 D:\workplace\code\test 这个前端项目的代码结构。
具体查：1.有哪些文件各自干什么 2.依赖关系 3.整体什么项目
约束：只读、不修改；聚焦结构，不贴大段源码。
输出：项目概览 / 文件清单 / 依赖关系 / 入口
子 agent 返回（节选）

项目概览：Three.js + MediaPipe 的 3D 粒子手势 demo——摄像头识别手张开程度，粒子随开合扩散/收缩，可切球形/爱心/土星。

文件清单：index.html（骨架）/ style.css（样式）/ models.js（几何生成）/ particle-system.js（粒子系统类）/ gesture-detector.js（手势识别类）/ main.js（主逻辑胶水）

依赖：main.js 驱动 particle-system + gesture-detector；particle-system 依赖 models.js。无循环依赖。

入口：index.html，main.js 在 DOMContentLoaded 时启动。

关键对比：单线程读 vs 派子 agent

单线程自己读

7 个文件全文全部进主会话上下文，几千 token 占掉工作记忆。后面想干别的就"喘不过气"。

派 Explore

子 agent 独立读完所有文件，主会话只收到一份总结。源码一行没进主上下文——上下文隔离。

给 prompt 的四要素（第四课深入）

任务
要它干什么
具体问题
查哪些点
约束
只读 / 不贴源码 / 不改其他
输出格式
要什么结构的结果

自包含、目标明确、有约束、指定输出——子 agent 拿到就能独立跑，不用回来问你。

练一练

测验 1：派 Explore 扫描 7 个文件后，这 7 个文件的全文会进入主会话上下文。
测验 2：给子 agent 的 prompt 应自包含——它不用回看主会话历史就能干活。
测验 3：调用 Agent 工具，至少要指定"派哪种子 agent"和"给它什么任务"。
