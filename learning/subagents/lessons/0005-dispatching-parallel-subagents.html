并行派发多个子 agent

一个子 agent 派出去要等一会。要是你有 3 个独立任务，串行派得等 3 倍。这课讲怎么让它们同时跑。

串行 vs 并行——时间账

串行派

任务 A → B → C，各 3 分钟，共 9 分钟。主会话干等三趟。

并行派

A / B / C 同时跑，共 3 分钟。主会话一次等完。

核心原则

每个独立问题域派一个 agent，让它们并发跑。主会话当调度员，等全部返回再整合。

多个独立任务 · 一人一个 · 同时出发 · 统一收口

什么时候能并行（三个条件）

不是"多个任务"就能并行，得同时满足：

独立任务之间不依赖（A 的结果不是 B 的输入）
无共享状态不会改同一个文件/资源、互不干扰
自包含每个任务不用看其他任务就能干

适合并行

3 个独立项目各做代码分析；3 个测试文件各有不同根因的失败；读代码 + 读文档 + 查依赖（三件不相关）。

不适合并行

任务相关（修一个可能修其他）；改同一文件（会冲突）；需先理解全局；还没摸清什么坏了。

四步走

  1. 识别独立域——按"什么活"分组，能分开的分开。
  2. 给每个 agent 聚焦任务——范围 + 目标 + 约束 + 期望输出（第 4 课四要素）。
  3. 并行派发——一条消息里放多个 Agent 工具调用。
  4. review 整合——读每个总结、查冲突、验证、整合。

关键技术点：怎么让它们"并行"

在 Claude Code 里，一条消息里放多个 Agent 工具调用，它们就并发执行。分多条消息发 = 串行。

# ✅ 一条消息多个调用 = 并发
Agent(subagent_type:"Explore", prompt:"分析 D:\...\raft1 的代码结构")
Agent(subagent_type:"Explore", prompt:"分析 D:\...\raft2 的代码结构")
Agent(subagent_type:"Explore", prompt:"分析 D:\...\raft3 的代码结构")
# 三个同时跑，主会话等全部返回

系统机制原话："send them in a single message with multiple tool uses so they run concurrently."

真实案例（来自 dispatching-parallel-agents）

6 个测试失败，跨 3 个文件

场景：大重构后，3 个文件各有失败——abort 逻辑 / 批量完成 / 竞态条件。三个域独立。

派发：Agent1 修 abort 文件 · Agent2 修批量完成文件 · Agent3 修竞态文件，并行。

结果：三个同时修完，互不冲突，全套测试转绿。省下串行的时间。

关键：判断"独立"是前提——若同根因，就该一起查而非拆开。

review 整合——别只收不管

  • 读每个 agent 的返回总结
  • 查冲突——可写 agent 是否改了同一文件（只读 Explore 不冲突）
  • 验证——修 bug 的话跑全套测试
  • 抽检——agent 会系统性出错，别全信，抽查关键结论

还是四要素（呼应第 4 课）

每个 agent 的 prompt 仍是四要素。并行时最常见的错误是太宽：

太宽

"把所有测试都修了" → agent 迷路。

聚焦

"修 agent-tool-abort.test.ts 这 3 个失败" → 范围明确。

练一练

测验 1：并行派发要求任务之间无共享状态、互不干扰。
测验 2：3 个失败如果是同一个根因引起的，应该拆成 3 个子 agent 并行查。
测验 3：让多个子 agent 并发跑，方法是在一条消息里放多个 Agent 工具调用。
