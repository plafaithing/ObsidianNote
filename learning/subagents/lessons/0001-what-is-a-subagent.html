子 agent 是什么

子 agent（subagent）就是主会话派出去的一个独立上下文的 Claude 实例。你给它一份精心构造的任务简报，它干完活，把结果交还给你。

关键在"独立上下文"四个字——它不继承你和 CC 之前的对话历史。它能看到什么，完全由你这一次给它的指令决定。

一个类比

你是项目经理，子 agent 是你派出去的专员。你不会把过去三个月所有会议记录都倒给他，而是递一份简报："去查 X，回来告诉我 Y。"他带着简报独立跑一趟，回来只交结论。

为什么要用它

两个好处，都和"上下文"有关：

1. 专注。子 agent 只看到任务相关的东西，不会被你会话里一堆无关内容干扰，更不容易跑偏。

2. 保护你的上下文。它读的文件、中间过程，都不塞进你的会话。你的"工作记忆"留给做决策、做协调，而不是被一堆搜索结果占满。

和"单线程"的区别

单线程（你现在的用法）

CC 自己读文件、改代码，所有东西堆进同一个上下文。活儿一多，上下文塞满，CC 开始"忘事"、变慢。

派子 agent

把"读一堆文件""排查某个问题"派出去，主上下文保持清爽。你像调度员，而不是亲自下场干每一件事。

小测验 1：子 agent 会自动继承主会话之前的全部对话历史。
小测验 2：派子 agent 去搜索 10 个文件，能保护主会话的上下文不被这 10 个文件的内容塞满。
小测验 3：子 agent 适合处理和主会话正在做的事紧密相关、需要随时看全局状态的活儿。

动手想一个

结合你平时的用法：想一个"CC 干得慢、或上下文不够用"的场景，写下来——那个场景，很可能就是该派子 agent 的地方。

写完不用自己判断对错——把它发给你的 agent 老师（就是带你学习的这个 Claude），一起讨论这个场景适不适合派子 agent。这其实就是你的第一次"判断该不该派"练习。
