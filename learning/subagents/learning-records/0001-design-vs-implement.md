# 0001 · 设计留主会话，实现派出去

> 学习记录 · 2026-06-26

## 背景
第 2 课练习，用户自己归纳出"该不该派子 agent"的两个场景：
- 适合派：CC 自行修改代码并测试
- 不适合派：需求设计时确认功能点细节（需来回交互）

## 洞察
用户无意识触及了子 agent 使用的核心分工：
- **设计 / 决策 / 确认细节**（要交互、要人判断）→ 留主会话
- **明确的实现 + 测试**（自包含、要结论、可验证）→ 派给子 agent

这正是 superpowers **SDD（subagent-driven-development）**工作流的精髓：主会话做规划和决策，把边界清楚的实现任务派给 implementer 子 agent 执行。

## 前提（用户判断需要补的）
"修改代码并测试"适合派，仅当任务**边界清楚、独立、可验证**（如"修复 X 的 Y bug，写测试，跑通"）。若是开放的"这个功能怎么改比较好"，属于探索 / 设计，不适合派——应留主会话讨论清楚后再派。

## 影响
- 后续教学可自然引入 SDD 循环（原计划为选学，现可作为延伸）
- 用户的真实工作流可能就是"设计 → 派实现"，后续课案例可据此设计
