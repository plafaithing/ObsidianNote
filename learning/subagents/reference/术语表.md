# 术语表 — 子 agent

> 课程中出现的术语，统一释义。新课遇到术语应与此一致。

## SDD
**Subagent-Driven Development（子 agent 驱动开发）**。一种用子 agent 执行实现计划的工作流：把计划拆成独立任务，每个任务派一个**全新**子 agent 实现，实现后过两道 review——先查规格符合（spec compliance），再查代码质量（code quality）——通过才进下一个，全部完成后再做整体 review。

核心公式：fresh subagent per task + 两阶段 review = 高质量、快迭代。

主会话是"控制器"（拆任务、派发、review、整合），子 agent 是"执行者"（实现单个任务）。正是"设计留主会话、实现派出去"的系统化版本。

详见 `superpowers:subagent-driven-development`。

## subagent（子 agent）
主会话派出去的、独立上下文的 Claude 实例。不继承主会话历史，只看这次给的指令。用于专注完成自包含任务、保护主上下文。

## 上下文隔离
子 agent 拥有独立上下文，其读写的文件 / 中间过程不进入主会话上下文。是子 agent "专注"和"保护主上下文"两个好处的根源。

## spec compliance review（规格符合审查）
SDD 第一道 review：检查实现是否严格符合任务规格——没多做（过度构建）、没少做（遗漏）。

## code quality review（代码质量审查）
SDD 第二道 review：检查实现写得好不好——可读性、复用、效率等。须在 spec compliance 通过后进行。

## fresh subagent per task
SDD 核心做法：每个任务派一个全新、上下文干净的子 agent，不复用前一个子 agent 的上下文，避免污染、保持专注。
