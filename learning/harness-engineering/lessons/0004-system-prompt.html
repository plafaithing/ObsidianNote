系统提示词层：作用、结构、写法

harness 七层的第一层。你其实早就在用——CLAUDE.md 就是系统提示词的一部分。

← 上一课：workflow vs agent 下一课：拆 CC system prompt →

你早就在用这一层

L01 把系统提示词列为 harness 第一层。你可能觉得它很陌生——但其实你写过：Claude Code 启动时会把 CLAUDE.md 的内容拼进 system prompt。你写在 CLAUDE.md 里的"用中文""别过度工程""先规划再实现"，都是在写系统提示词层。

系统提示词是什么？它是每次对话开始时注入的持久指令，塑造 agent 整场的行为——区别于用户消息（临时、一次性的）。用户消息是"这轮请你干什么"，系统提示词是"你是个什么样的 agent、永远遵守什么"。

作用：四件事

作用例子
① 身份与角色"你是一个 Python 编码助手"——聚焦行为和语气
② 规则与约束"改代码前先读文件""危险操作要确认"
③ 输出格式"用流畅散文，别用 markdown 列表"
④ 上下文与背景"当前日期是 X""这是售前场景，要可控可承诺"

结构：用 XML 标签分块

Anthropic 的建议：复杂系统提示词用 XML 标签分块，让 Claude 无歧义解析哪部分是指令、哪部分是上下文、哪部分是例子。

<role>你是一个代码审查助手，专注 Python。</role>

<instructions>
1. 改代码前必须先读文件
2. 只改用户要求的，不顺手重构
</instructions>

<context>当前是售前 POC，稳定性优先于功能丰富度。</context>

<examples>
<example>...</example>
</examples>

标签名要一致、描述性；可嵌套。这一层做对了，后面 L05 你看 Claude Code 的真实 system prompt 时，会发现它正是这么组织的。

写法四原则

① 清晰直接（黄金法则）

把 Claude 当成聪明但缺背景的新员工。Anthropic 的黄金法则：把你的 prompt 给一个不了解任务的同事看，如果 ta 会困惑，Claude 也会。顺序重要就用编号列表，输出格式要具体。

② 说"做什么"，别说"不做什么"

✗ 别这样
不要用 markdown
✓ 这样
用流畅的散文段落

正面指示比负面禁止有效得多。Claude 更容易按"做什么"执行，而不是反向推理"不做什么之后该做什么"。

③ 给例子（few-shot）

3-5 个好例子比长篇描述更稳。例子要 Relevant（贴近真实用例）/ Diverse（覆盖边缘情况）/ Structured（用 <example> 标签包，和指令区分开）。

④ 给角色

哪怕一句话角色设定都能聚焦行为："你是一个帮助 DBA 诊断慢 SQL 的助手" 比 "你是一个助手" 强得多。角色定了，语气、知识范围、默认行为都跟着收敛。

关键洞察：系统提示词是 harness 各层的"控制面板"

这是 agentic 场景下系统提示词最值钱的用法——你不只写身份，还能在里面调控 harness 其他层的行为。Anthropic 文档里给了不少真实片段：

  • 调控工具层：想让 Claude 默认动手而非只建议，加 <default_to_action>；想保守就加 <do_not_act_before_instructions>。（→ L07 工具循环）
  • 调控安全层：告诉它哪些操作要确认——"删除文件、force push、影响共享系统的操作，先问用户"。（→ L14 安全设计）
  • 调控编排层：subagent 用过头了，加"简单任务直接干，别派 subagent"。（→ L15 编排层）
  • 防过度工程：加"只做要求的改动，别加抽象、别补 docstring"——这正好是你 CLAUDE.md 里写的。（→ 售前可控性）
  • 调控上下文层：告诉它"上下文会自动压缩，别提前停"。（→ L09 上下文管理）
记住这个视角

系统提示词不只是"角色设定"，它是 harness 各层行为的控制面板。很多你以为是"工具/权限/编排"层的事，其实是在系统提示词里一句话调控的。这也是为什么售前定制 agent 时，系统提示词往往是投入产出比最高的一层——改一句话，行为大变。

反模式（别这么写）

三个坑

① 激进语言：新模型对系统提示词更敏感，"CRITICAL: You MUST use this tool when..." 会导致过度触发。改成正常的 "Use this tool when..." 即可。

② 只写 don't："不要 hallucinate""不要改测试"——模型不知道该做什么。换成正面指令。

③ 模糊："表现得专业一点"——没用。具体到"用中文、改代码前先读、只改要求的"。

小练习：想让 Claude Code 默认"直接动手改代码"而不是只给建议，系统提示词该怎么写？

✓正面写"默认实施改动"
✓写"不要只给建议"
✓用 CRITICAL MUST 强制
✓什么都不写就行

答案：正面写"默认实施改动"。两条原则叠加：① 说"做什么"别说"不做什么"——"不要只给建议"是负面，不如正面写"默认实施改动而非建议"；② 新模型对激进语言过敏，CRITICAL MUST 会过度触发，正常语气即可。这就是 Anthropic 文档里 <default_to_action> 片段的思路。
