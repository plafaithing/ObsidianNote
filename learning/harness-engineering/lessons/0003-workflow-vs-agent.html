workflow vs agent

谁决定下一步——代码还是模型？这是售前最常被问的判断题。

← 上一课：agentic loop 下一课：系统提示词层 →

从 L02 那个 while 说起

上一课你手写的 while stop_reason == "tool_use"，是 agent 的最小形态——模型自己决定调什么、什么时候停。但很多场景你不想要这种自主：你要的是可预测、可控、能承诺的结果。这时候你要的是 workflow。

Anthropic 在 Building Effective Agents 里把所有"LLM + 工具"系统统称 agentic system，但做了个关键架构区分：

Anthropic 原文定义

Workflow：LLM 和工具通过预定义代码路径编排——走向写死在代码里。

Agent：LLM 动态指挥自己的流程和工具使用——模型自主决定怎么完成。

本质区别：谁决定下一步

Workflow（固定链）

走向由代码决定。模型只在每个节点被调一次，干具体的活，但不决定下一步去哪。

outline = llm("写大纲")
check_outline(outline)   # 程序检查
doc = llm("按大纲写正文")
translate = llm("翻译成英文")

Agent（自主循环）

走向由模型决定。L02 那个 while——模型在循环里自己挑工具、自己决定继续还是停。

while model_wants_tools:
    tool = model.choose()
    result = run(tool)
    feed_back(result)   # 模型决定下一步

一句话：workflow 把 while 换成了固定的步骤链。代码掌控走向 = workflow；模型掌控走向 = agent。

Anthropic 的忠告：别为了 agentic 而 agentic

原文核心建议

"找最简单的方案，只在需要时增加复杂度。这可能意味着根本不建 agentic 系统。" 很多时候，优化单个 LLM 调用（加检索、加 in-context 示例）就够了。

agentic 系统是用延迟和成本换任务性能。这个交易不一定划算：

WorkflowAgent
走向可预测、一致灵活、模型驱动
适合定义良好、步数固定的任务开放、步数不可预测的任务
代价低、可控高成本、错误会复合
控制强（走向写死）弱（需 guardrails、停止条件）

售前判断框架：三个问题

客户说"我要一个 agent"——你先别急着给 agent，问自己三件事：

  1. 任务步数能预测吗？ 能 → workflow；不能（要模型边走边探索）→ agent。
  2. 需要模型自主决策吗？ 只是按固定流程处理 → workflow；要在执行中判断分叉 → agent。
  3. 能接受延迟和成本换性能吗？ 客户要快、要便宜、要可控 → 别上 agent，甚至别上 agentic。
售前最常见的坑

客户嘴上说"要 agent"，往往其实要的是 workflow——要可预测、可控、能承诺 SLA。硬上 agent = 成本高、不可控、错误复合、难交付。识别"该用 workflow 的别硬上 agent"，是售前最值钱的一句话。

两个对照例子

  • 客服工单分流：把工单分类（退款/技术/咨询）转给不同处理流程。分类可预测、走向写死 → workflow（routing 模式）就够，不必 agent。
  • 改多文件修 bug：要读代码、定位、改、跑测试，步数不可预测，要模型边走边探索 → agent。Claude Code 干的就是这个。

判断口诀：能写死就写死（workflow），写不死才自主（agent）。

伏笔：workflow 还有 5 种模式

workflow 不是只有"固定链"一种。Anthropic 细分了 5 种编排模式：prompt chaining（提示链）/ routing（路由）/ parallelization（并行）/ orchestrator-workers（编排者-工人）/ evaluator-optimizer（评估器-优化器）。这些留到模块 5 编排层（L15-L17）展开——其中 orchestrator-workers 有点像 agent，但子任务由编排者动态决定、非完全自主，是个中间形态。

小练习：客户要"把工单分类后转给不同处理流程"的系统，该优先考虑？

✓workflow（路由模式）
✓agent（自主循环）
✓两者没区别
✓必须用 agent

答案：workflow（路由模式）。工单分类可预测、处理流程写死——典型 routing workflow。上 agent 反而引入不必要的成本和不可控。售前的价值正在于此：客户说"要智能"，你判断出"这其实是个分类路由问题"，给可控可承诺的 workflow，而不是硬塞一个自主 agent。
