为什么需要循环

上一课说 harness 七层里有"②工具 + 工具循环"。这节专讲这个循环。

关键事实：模型一次 API 调用，只会返回一个响应。它要么直接回答你，要么说"我要调某个工具"。要完成一个真实任务（比如"读文件、找到 bug、改掉它"），往往要调好几次工具——每调一次，都得把结果送回模型，让它决定下一步。

所以模型自己不会"循环"，是 harness 在外面套了个 while 循环，反复调用模型直到它不再要工具。这个循环，就是 agent 的心跳——叫 agentic loop。

loop 长什么样

用户消息 → 模型决策 → 执行工具 → 把结果喂回模型 → 再决策 ↻ ↑ 只要模型还想调工具，就回到"执行工具"再走一圈；不想调了，输出最终回答

每一圈做三件事：① 模型决定要不要调工具 → ② harness 执行工具拿结果 → ③ 把结果塞回上下文，让模型继续。模型说"我不用调工具了"的那一刻，循环结束，输出回答。

手写最小 agent（Client SDK 版）

别被"agent"吓到——剥到最底，它就是一个 while 循环。这是用 Anthropic 底层 Client SDK 写的最小 agent，循环是你自己写的：

# 1. 第一轮：把用户问题 + 工具清单发给模型
response = client.messages.create(
    model="claude-sonnet-4-5",
    messages=[{"role": "user", "content": "当前目录有哪些文件？"}],
    tools=[...],                      # 工具定义（schema + 描述）
)

# 2. agentic loop：只要模型还想调工具，就继续转
while response.stop_reason == "tool_use":
    tool_call = response.content      # 模型说：我要调这个工具
    result = run_tool(tool_call)      # harness 真正执行工具，拿结果
    response = client.messages.create(   # 3. 把结果喂回，让模型继续决策
        model="claude-sonnet-4-5",
        messages=[...旧历史, tool_call, result],   # 历史里追加这一轮
        tools=[...],
    )

# 4. 模型不再调工具 → 循环退出，输出最终回答
print(response.content)

读懂这三处就够：第一，while 的条件 stop_reason == "tool_use" 是模型在说"我还要调工具"；第二，run_tool 是 harness 干的活（执行工具）；第三，每轮把工具结果追加进 messages 再发给模型——这就是"喂回"。

小胜利

你现在能说出 agent 到底"自主"在哪了：模型决定调哪个工具、什么时候停，harness 只负责执行和喂回。所谓自主，就是模型掌控循环的走向，而不是代码写死下一步。

Agent SDK 把循环藏去了哪里

上面那段 while，你得自己写、自己维护工具执行、自己拼消息历史。Claude Agent SDK 把这整段循环封装进了一个 query 调用——同样的 agent，代码变成这样：

# Agent SDK：循环被封装了，Claude 自主处理工具
async for message in query(
    prompt="当前目录有哪些文件？",
    options=ClaudeAgentOptions(allowed_tools=["Bash", "Glob"]),
):
    print(message)

没有 while，没有 run_tool，没有手动拼历史。那个循环还在——只是 Claude 替你转了，你只管流式收结果。

Client SDKAgent SDK
谁写 agentic loop你自己（while 循环）Claude 替你转
谁执行工具你写 run_tool内置工具开箱即用
谁管消息历史你手动拼SDK 自动维护
适合要完全掌控每一步快速搭 agent / 生产用
记住这个对照

这就是 L01 说的"Claude Agent SDK 是 Claude Code 的开源内核"在代码层面的证据——CC 那个能读文件改代码的 agent，内核就是这样一个被封装好的 agentic loop。模块 8 我们会打开 Agent SDK 源码，看这个循环在代码里到底怎么写。

小练习：agentic loop 每一圈"喂回模型"的，是什么？

✓工具执行的结果
✓用户的下一条指令
✓系统提示词更新
✓压缩后的旧历史

答案：工具执行的结果。loop 的三件事是"模型决策 → 执行工具 → 把结果喂回"。喂回的是 run_tool 的产出，模型据此决定下一步。用户的下一条指令要等这轮 loop 结束才出现；系统提示词一般整轮不变；压缩历史是上下文管理的事（L09），不是 loop 每圈喂的东西。

带着这个进下一课 你刚看到 agent 的核心是"模型掌控走向的循环"。但 Anthropic 还有一类系统叫 workflow——走向是代码写死的，不让模型自己决定。下一课就拆这对概念：什么时候该用 workflow，什么时候必须上 agent？这是售前最常被客户问的判断题之一。
