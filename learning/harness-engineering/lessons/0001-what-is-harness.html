从一个问题开始

你天天用 Claude Code：让它读文件、改代码、跑命令、调试。但模型本身只会一问一答——它没有手，看不见你的硬盘，记不住上一轮对话之外的事。那它是怎么变成"能动手干活"的 agent 的？

答案是：模型外面裹了一层工程脚手架。这层脚手架，叫 harness（字面是"线束 / 马具"，引申为"套在模型身上的那套装备"）。Claude Code，就是一个完整 harness。

一句话定义

harness = 包裹基础模型的那层工程，把"会聊天的模型"变成"能可靠干活的 agent"。本课程要做的，就是把它从黑盒拆成透明结构。

第一步：裸模型 → 增强 LLM

Anthropic 在 Building Effective Agents 里给了一个基础构建块——augmented LLM（增强 LLM）：在裸模型上加上三样东西。

基础模型 + 检索 + 工具 + 记忆 = 增强 LLM
  • 检索：能去外部找信息（搜网、查知识库），不是只靠训练时记的。
  • 工具：能调函数/命令真正"动手"（读文件、跑脚本、改代码）。
  • 记忆：能保留上下文与状态，不是每轮从零开始。

增强 LLM 是 harness 的起点，但还不是完整的 harness——还缺"怎么循环、怎么管权限、怎么编排"这些工程层。下面把它们补齐。

agent 解剖图：harness 的七层

一个成熟 harness（以 Claude Code 为样本）大致由这些层组成。先建立总图，后续每节课深入一层：

层干什么在 Claude Code 里的样子
① 系统提示词塑造行为：身份、规则、约束、格式CC 启动时注入的超长 system prompt
② 工具 + 工具循环给模型"手脚"，并循环：决策→调工具→喂回→再决策Read/Write/Edit/Bash/Glob/Grep… + agentic loop
③ 上下文管理管窗口：什么进上下文、什么压缩/丢弃CC 的上下文自动压缩
④ 记忆 / 状态跨轮/跨会话持久化上下文CLAUDE.md、session
⑤ 权限与安全约束能做什么、防越界allow/deny/ask 权限规则、hooks
⑥ 编排组织工作流：单 agent 还是多 agent 协作subagents（.claude/agents/）
⑦ 可观测性让 agent 可被观察、可恢复日志、成本追踪、中断恢复
关键事实

这七层不是抽象理论——Claude Agent SDK 就是 Claude Code 的开源内核（官方原话："the same tools, agent loop, and context management that power Claude Code"）。也就是说，读 Agent SDK 的代码，就是读 Claude Code 这七层的实现。本课程中后期会逐层对照源码。

这跟你的两个目标有什么关系

你学这门课有两个落点，它们都建立在"分层"视角上：

  • 定制 Claude Code：你日常配的 CLAUDE.md、hooks、权限规则、subagents，每一个都是在改 harness 的某一层。看清改的是哪层，才知道效果和副作用。
  • 售前定制 agent：客户要一个 agent，本质是"帮 ta 决策这七层各自怎么做"。有这张总图，你就有切入点，而不是无从下手。

小练习：在 Claude Code 里，CLAUDE.md 文件最属于 harness 的哪一层？

✓上下文与记忆层
✓权限与安全层
✓工具与循环层
✓编排与分发层

答案：上下文与记忆层。CLAUDE.md 是项目级记忆——Claude 每次启动都读它，把里面的指令/偏好注入上下文，塑造行为。它不直接控制权限、不定义工具、也不派 agent。带上这个"归层"习惯，后面每学一个 CC 功能，都问一句：它改的是哪层？

带着这个进下一课 想一个你用 Claude Code 时观察到的"行为"（比如：它有时候会自动压缩历史、有时候会停下来问你确认、有时候会自己派子 agent）。猜猜它属于七层里的哪一层？把你的猜测带着走——后续课程会逐一验证或推翻。
