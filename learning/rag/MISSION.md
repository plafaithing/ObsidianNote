# RAG 课程 Mission

> 学什么：检索增强生成（Retrieval-Augmented Generation），聚焦「运维知识库 RAG」场景
> 为什么学：求职 AI 售前/解决方案岗，RAG 是必备 + 核心缺口

## Why（为什么学）
- 求职 AI 售前/解决方案岗。简历 Gap 分析中，RAG / Agent / 框架是「必备」缺口，RAG 标记为「核心」。
- 面试要能讲清 RAG 各环节取舍；手里要有可演示的 demo；能为客户设计 RAG POC。
- 第一个王牌 demo 是 DBA Copilot（数据库智能运维助手），其中「运维知识库 RAG」是核心组件。

## 成功标准
1. **搭**：用 Dify 搭一个能跑的运维知识库 RAG demo，并能读/改 LangChain 代码片段
2. **讲**：能讲清 chunking / embedding / 检索 / rerank / 评估 的取舍（售前面谈核心）
3. **设计**：能为企业客户设计 RAG POC 方案（选型、效果评估、数据治理、成本）
4. **扛**：能扛住面试官对 RAG 的深度追问（企业实战痛点 + 高频面试题）

## 约束
- 周期：约 2 周（与简历计划对齐）
- 基线：Python 能读不能流畅写；调过 LLM API；prompt 仅常规交流，未专门研究
- 路径：混合（概念 + Dify 低代码出 demo + 补够代码能读改 LangChain）
- 背景优势：数据库 + 售前方法论可迁移

## 范围外
- 不训练模型、不深挖算法实现（如 Transformer 内部）
- 不做生产级工程（高并发、分布式等）
- Agent / 工具调用留作下一门课（本课只在综合应用处轻触及）

## 北极星 demo
**运维知识库 RAG**：把数据库运维文档（慢 SQL 诊断、会话分析、SQL 限流等）做成知识库，用户自然语言提问 → 检索相关运维知识 → 生成带引用的解答。这是 DBA Copilot 的 RAG 部分，Agent 部分留作后续课程。
